# Splat lab · method G2 — DiffSplat on our GTX 1070 (k8s Job)

**Text prompt → 3D Gaussian splats, generated once on a 2016 consumer card inside the home
k8s cluster.** DiffSplat (ICLR 2025, MIT) is a *feed-forward* splat generator: one pass of a
fine-tuned SD1.5 U-Net writes a 4-view latent grid, the GSVAE decoder turns each latent pixel
into a Gaussian, and the result is exportable straight away — no per-object optimisation. The
authors quote **1–2 s per object**, on an A100.

Everything here was produced by Job `splat-lab-diffsplat-3` (2026-11-17, node `dave-droid`,
GTX 1070, HAMi slice 5000 MiB). No measured product dimensions, no real hardware geometry: the
objects are hallucinated from the words in the prompt.

The SD1.5 generator was chosen over PixArt-Sigma (0.61 B) and SD3.5-medium (2.24 B) because
PixArt-Sigma needs the T5-XXL text encoder (~4.7 GB fp16) and SD3.5m does not fit at all; with
SD1.5 the whole generation set is 2.33 GiB resident in fp16 and the peak stays under 2.9 GiB.

## Generator command (as run inside the Job)

```bash
# /data/cache/g2/run.env is written by job/setup.sh (venv + maybe the stub rasterizer path)
"$G2_PYTHON" /scripts/run.py \
    --out /data/out/diffsplat-3 --repo /data/cache/repo/DiffSplat \
    --ckpt /data/cache/ckpt/DiffSplat --prompts /scripts/prompts.tsv \
    --seed 0 --steps 20 --guidance-scale 7.5 --elevation 10 --res 256 --precision fp16
```

Which is the upstream text-conditioned SD1.5 recipe
(`bash scripts/infer.sh src/infer_gsdiff_sd.py configs/gsdiff_sd15.yaml gsdiff_gobj83k_sd15__render
--prompt … --save_ply`) with our defaults kept — 20 `sde-dpmsolver++` steps, CFG 7.5, empty
negative prompt, elevation 10°, camera radius 1.4, 256² per view, 4 views at azimuth
0/90/180/270° — and three deliberate changes, all forced by the hardware:

1. **fp16 instead of fp32/bf16.** Upstream's script autocasts to fp32 (or to **bf16** with
   `--half_precision`); its fp32 U-Net alone is 3.44 GB and does not fit in the 4.9 GiB slice
   next to the rest. Pascal has no bf16 tensor cores, so the generation-side modules (CLIP text
   encoder, SD1.5 VAE, the 859.5 M-param multi-view U-Net) are loaded fp16 and the loop runs
   under `torch.autocast("cuda", torch.float16)`; the GSVAE decode + unprojection stay fp32.
   Nothing was NaN/inf: `run.py` aborts an asset whose positions or colours are non-finite, and
   none did. (`torch.cuda.is_bf16_supported()` does report `True` here — an fp16-vs-bf16
   comparison on this card is a follow-up, `--precision bf16` is wired up.)
2. **No GSRecon weights.** Upstream loads them but, per its own README, only uses the class's
   rendering function at inference; `run.py` recomputes the same Gaussian-parameter math
   (depth + camera-distance → `unproject_depth`, `rgb·0.5+0.5`, the inverted
   `scale_min·x + scale_max·(1−x)` activation, opacity `·0.5+0.5`) and writes the `.ply` in
   upstream's `compatible=True` column semantics. This saves a 160 MB download and means the
   exported splats never depend on the CUDA rasterizer.
3. **`--save_ply` equivalent, no video.** The deck renders the splats itself, so no `.gif`/`.mp4`
   was requested — that is also the only thing the rasterizer is needed for.

Rasterizer status: the sm_61 build **compiled and imported** (78 s, `TORCH_CUDA_ARCH_LIST=6.1`,
`--no-build-isolation`, `MAX_JOBS=4`), so DiffSplat's dependency is satisfied on Pascal; but the
optional 16-view verification sheet failed for an unrelated upstream reason (below), so the
geometry was checked with `tools/splats/g2/preview.py`, an offline CPU rasterizer whose output is
in `tools/splats/g2/preview/`. Under the deck's luminance-only post shader the assets read as:
GPU = a chunky shroud with an axial-fan X, server = a slim tower on a foot, books = a stack of
two volumes with visible page faces.

## Post-processing (this repo, CPU only)

```bash
POD=$(kubectl get pod -l app=splat-lab-files -o name | cut -d/ -f2)
kubectl cp default/$POD:/data/out/diffsplat-3 /tmp/g2-out
bash tools/splats/g2/make.sh /tmp/g2-out
#   normalize.py : opacity > 0.02, robust 0.5/99.5 percentile box +15 % margin, recentre,
#                  scale largest extent to 4.0 units, sigmas × same factor, quaternions
#                  renormalised, y-up / handedness untouched
#   preview.py   : offline sanity render (luminance -> 6-tone sage, like the deck's shader)
#   splat-transform@3.11.2 -w in.ply out.spz   (and `out.spz --stats null` for the table above)
```

Export → `.spz` retained 19–29 % of splats (262 144 → 51–81 k) because two thirds of the
decoder's Gaussians have opacity ≤ 0.02: each of the 4 views paints 65 536 near-transparent
Gaussians over the same volume. Positions are all finite; nothing was cropped by the robust box
(`dropped_outside_robust_box: 0` for all three), so the crop only protected the scale step.

## Honest limits — what these assets must not be used to claim

- **Not real hardware.** "a graphics card with a large cooler" produced a plausible cooler-shaped
  box, not an RX- or RTX-class board. No measured dimensions, no port/PCIe geometry, no fan
  model. The prompts are the only input.
- **Not DiffSplat's headline speed.** 53.4 s per object here vs the paper's 1–2 s: same model,
  same step count, seven-year-old GPU without tensor cores. The *shape* of the claim
  ("feed-forward, seconds not minutes, no per-object training") survives; the number does not.
- **fp16 is our deviation.** The paper's metrics are fp32 on A100; quantising the U-Net to fp16
  can shift outputs (same seed, different weights → different object). Treat these as
  "one sample from the model", not as reference quality.
- **262 144 Gaussians is 4 × 65 536 view-lifts, not one clean surface.** Adjacent views overlap,
  so orbiting reveals double-wall artefacts and the silhouettes are soft. Opacities are low
  (mean 0.18–0.35 after filtering): the objects look volumetric/ghostly, which is a property of
  this generator, not of the deck's renderer.
- **Scale is arbitrary.** The assets are centred and rescaled so the largest extent is 4 units
  (the deck's default ortho view). Nothing in an asset encodes an absolute size.
- **The generator is a text-conditioned diffusion model**: seed 0, CFG 7.5, 20 steps — a different
  seed gives a different card. It is not deterministic across step counts either.

## Upstream findings worth keeping (all reproduced 2026-11-17)

1. `UNetMV2DConditionModel.from_pretrained_new(…, low_cpu_mem_usage=True)` crashes with
   `UnboundLocalError: state_dict_original` (`unet_mv2d_condition.py:1661` reads a name only bound
   in the `low_cpu_mem_usage=False` branch at `:1634`). Upstream never hits it because
   `src/infer_gsdiff_sd.py` passes `False`; we do too now, at ~10 GB CPU peak instead of ~5 GB.
2. `src/infer_gsdiff_sd.py` sets `noise_scheduler.config.rescale_betas_zero_snr = True` *after*
   `from_pretrained`; in diffusers 0.32.2 that flag is consumed in `__init__` (it rescales
   `self.betas`), so upstream's "common tricks" only really apply `timestep_spacing="trailing"`.
   `run.py` reproduces upstream's effective behaviour and logs it; `--rescale-betas-zero-snr-at-init`
   is there if you want the flag to actually take effect. `algorithm_type` *is* read dynamically
   from the config, so `sde-dpmsolver++` does apply.
3. DiffSplat's `settings/setup.sh` clones RaDe-GS `main`, and today's `main` no longer accepts
   the `require_coord=` keyword its own `render()` passes → the preview render path is broken
   against a fresh install (`TypeError: GaussianRasterizationSettings.__new__() got an unexpected
   keyword argument 'require_coord'`). Export is unaffected; fixing the sheets means pinning an
   older RaDe-GS commit.
4. `pytorch/pytorch:2.7.1-cuda12.6-cudnn9-devel` has **no `git` binary**, and `pip wheel` on a
   CUDA extension needs `--no-build-isolation` to see the image's torch. Both are handled by
   `job/fetch_sources.py` (codeload tarballs + `tarfile(filter="data")`) and `job/setup.sh`.
5. GitHub archive tarballs contain RaDe-GS's `submodules/diff-gaussian-rasterization/**` (it is a
   plain directory in that repo) but **not** `third_party/glm` (a real submodule) — glm has to be
   fetched separately at the pinned commit.
